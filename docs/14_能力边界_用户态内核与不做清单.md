# 设计 05：能力边界（用户态可做 / 必须内核 / 建议不做）

## 一、用户态完全可做（M0/M1，90% 的检测价值在这里）

| 能力 | 实现路径 | 备注 |
|---|---|---|
| 全量进程枚举 | `NtQuerySystemInformation(SystemProcessInformation)` | 一次调用拿全表，含 PPID/会话/映像名 |
| 进程命令行 | WMI `Win32_Process.CommandLine` | 慢（~0.3-1s），按需查；受保护进程拿不到 |
| 进程映像路径 | `QueryFullProcessImageNameW` + `PROCESS_QUERY_LIMITED_INFORMATION` | 最小权限，不读内存 |
| 父进程链 | 从进程表建 PID→PPID 图，检测启动链异常 | 纯计算 |
| 数字签名 | `WinVerifyTrust` + `CryptCATAdminCalcHashFromFileHandle`（目录签名） | 必须两路都查，否则大量系统文件误判 |
| 已加载模块（仅非保护进程） | `EnumProcessModulesEx` / `CreateToolhelp32Snapshot(TH32CS_SNAPMODULE)` | 受保护进程会失败，跳过并标注 |
| 监听端口与连接 | `GetExtendedTcpTable` / `GetExtendedUdpTable` | 直接给 PID，用于组合信号 |
| 文件遍历 + SHA256 | `FindFirstFileEx` W 版 + 流式 `SHA256` | 只读，限制深度/数量 |
| PnP 设备枚举 | `SetupDiGetClassDevs` + `SetupDiGetDeviceRegistryProperty` / `CM_Get_DevNode_Property` | 拿 VEN/DEV/SUBSYS/REV/ClassCode/驱动服务名 |
| 设备内存窗口（近似 BAR） | WMI `Win32_PnPAllocatedResource` + `Win32_DeviceMemoryAddress` | 拿到的是资源分配区间，不是真实 BAR 寄存器值，够做"超大窗口"异常判断 |
| 驱动/服务清单 | `EnumServicesStatusEx` + 注册表 `HKLM\SYSTEM\CurrentControlSet\Services` | 只看，不改 |
| 规则引擎 / 评分 / 报告 / 日志 | 纯托管代码 | 全部用户态 |

## 二、必须内核辅助（M2 独占）

| 能力 | 为什么用户态做不到 | 内核实现方式 |
|---|---|---|
| **PCIe 配置空间前 64 字节** | 用户态无 IO 端口权限、无 MMIO 映射权限；`NtQuerySystemInformation` 不暴露配置空间 | 向设备栈下发 `IRP_MN_READ_CONFIG`（`BusInterfaceType = PCIBus`） |
| **Capability 链表** | 配置空间 0x34 起的链式结构，只能从配置空间读 | 同上，按 `Capability ID` 逐级读 |
| **MSI / MSI-X 能力与地址** | 属配置空间 0x34+ 区域 | 同上 |
| **真实 BAR 大小（寄存器回读）** | 需要"写全 1 再回读"的写操作 | 需 `IRP_MN_WRITE_CONFIG` —— **本方案禁止**，改用资源报告近似值 |
| **不在 PnP 树里的隐藏 PCIe 设备** | 用户态只能看枚举结果 | 遍历总线号 0-255 + 设备/功能号，读 `VendorId == 0xFFFF` 过滤 |
| **设备被反作弊/驱动隐藏后的可见性** | — | 同上，直接读总线而不是读 PnP 树 |

> 结论：内核部分只解决"配置空间读不到"这一件事，且**只用 READ_CONFIG**。BAR 大小走用户态资源报告近似，避免任何写配置空间的风险动作。

## 三、建议不做（明确划出范围）

| 不做的事 | 原因 |
|---|---|
| 读取游戏进程内存 / dump 游戏内存 | 与"只读查询工具"定位冲突，且直接踩反作弊红线 |
| 注入 DLL、`CreateRemoteThread`、APC 注入 | 同上 |
| API Hook、IAT/EAT patch、`SetWindowsHookEx` | 同上 |
| 内核常驻驱动、`ObRegisterCallbacks` 拦截句柄、进程保护 | 变成"反反作弊"组件，超出工具定位 |
| ETW Threat-Intelligence 消费者 | 需要微软特批签名，且与反作弊抢事件源 |
| 任何"绕过/禁用/干扰反作弊"的功能 | 硬性约束 |
| 修改注册表安全项、关 HVCI/Secure Boot、开 testsigning | 硬性约束 |
| 伪装进程名/签名、驱动隐藏 | 会让反作弊把我们列入可疑名单，反而制造冲突 |
| 自动封号/自动判定 | 报告只给等级，人工复核 |
| 内核态内存扫描、物理内存读取 | 与 DMA 检测无关，纯风险 |

## 四、一句话总结

- **用户态能做完 90%**：进程、文件、签名、端口、PnP 设备、规则、评分、报告。
- **内核只补 10%**：PCIe 配置空间的 Capability/BAR/MSI 细节，用一次性 READ_CONFIG 驱动，用完即卸。
- **风险最高的那 30% 能力（内存/注入/Hook/常驻内核）一个都不做**，这是这个工具能长期和安全环境共存的前提。
