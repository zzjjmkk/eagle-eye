## 二、模块划分

| 模块 | 职责 | 依赖 | 是否用户态 |
|---|---|---|---|
| `Cli` | 参数解析、退出码、进度输出 | Core, Rules, Dma | 是 |
| `ScanOrchestrator`(Core) | 编排：加载规则→跑检测器→聚合→评分→出报告 | 全部 | 是 |
| `IProcessSource` | 进程枚举抽象，3 种实现：NTAPI / Toolhelp / WMI | — | 是 |
| `ProcessDetector` | 名称/路径/命令行/父进程/模块匹配 | Rules | 是 |
| `SignatureVerifier` | 文件签名 + 目录签名 + 吊销检查（可离线缓存） | wintrust.dll | 是 |
| `FileDetector` | 目录只读遍历 + 名称规则 + SHA256 名单 | Rules | 是 |
| `PortEnricher` | GetExtendedTcpTable → PID 反查，供组合信号 | — | 是 |
| `DmaDetector` | WMI/SetupAPI 枚举 + 调用内核枚举 + 异常规则 | Rules, DriverClient | 是 |
| `DriverClient` | 加载→IOCTL→读 JSON→卸载，全程超时与审计 | pcieenum.sys | 是（驱动是内核） |
| `ScoringEngine` | 单条置信度 + 组合规则 + 白名单衰减 → risk_score | Rules | 是 |
| `ReportWriter` | JSON / HTML / 文本三选一 | Core.Models | 是 |
| `AuditLogger` | JSONL：OpenProcess 目标+访问掩码、驱动加载/卸载、WMI 查询 | — | 是 |
| `pcieenum.sys` | 枚举 PCI 总线，返回配置空间 JSON | WDM | 否（内核） |

## 四、关键实现选择（避免踩坑）

1. **进程枚举**：主路径 `NtQuerySystemInformation(SystemProcessInformation)` 一次拿到全量（含 PPID、会话、映像名），比 WMI 快一个数量级；Toolhelp 作为兜底；WMI 只用来补 CommandLine（`Win32_Process.CommandLine`），并且只在需要时查。
2. **打开进程的权限**：只用 `PROCESS_QUERY_LIMITED_INFORMATION`。绝不请求 `PROCESS_VM_READ`。拿不到就跳过并记录 `ACCESS_DENIED`，报告里写"未检查"。
3. **模块列表**：`EnumProcessModulesEx(...LIST_MODULES_ALL)` 需要 QUERY_INFORMATION + VM_READ 才能取路径 → 对普通进程可行，对 PPL/反作弊进程会失败。失败即跳过，不降级为强开。
4. **签名验证**：`WinVerifyTrust` 单文件签名 + `CryptCATAdminCalcHashFromFileHandle` 目录签名两路都查，否则会把大量 Windows 组件误判为未签名。
5. **命令行为什么难**：读 PEB 需要 VM_READ。所以默认走 WMI；WMI 也拿不到（受保护进程）就标 `commandLine: "unavailable"`。
6. **驱动生命周期**：`CreateService(START_DEMAND)` → `StartService` → `CreateFile("\\.\PcieEnum")` → `DeviceIoControl` → `CloseHandle` → `ControlService(STOP)` → `DeleteService`。任何一步失败都走 `onLoadFailure: degrade`，用户态结果照出，报告标"配置空间未采集"。
7. **超时与取消**：每个检测器 `CancellationTokenSource(TimeSpan)`，`maxScanSeconds` 兜全局。驱动 IOCTL 单独 `ioctlTimeoutMs`，超时强制卸载。
8. **不可变性**：`Finding` 是 record，评分阶段只读；白名单命中不改原 Finding，只在汇总时降权，保证报告可追溯。
