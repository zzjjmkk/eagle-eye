# 设计 03：分阶段开发计划

总周期约 5-6 周（单人或小团队），每阶段都有可运行产物，不做"最后一次性集成"。

## Phase 0 — 地基（3 天）

- 建 sln、4 个项目、Directory.Build.props、global.json
- `Models`：`Finding / Evidence / ScanContext / RiskLevel / ScanOptions`
- `RuleStore` + Schema 校验（加载失败即报错退出）
- `AuditLogger`（JSONL）：记录 OpenProcess 目标与访问掩码、WMI 查询、驱动加载
- CLI 骨架：`scan / rules validate / rules diff / report view`
- **自检工具** `tools\verify-no-touch.ps1`：扫描源码确认无 `PROCESS_VM_WRITE`、无 `WriteProcessMemory`、无 `SetWindowsHookEx`

交付：能跑 `probe rules validate rules\rules.example.json` 并输出 OK。
验收：Schema 故意写错时能指出 JSON 路径；自检脚本零告警。

## Phase 1 — 进程 + 签名（1 周）

- `IProcessSource` 三实现（NTAPI 主 + Toolhelp 兜底 + WMI 补命令行）
- `SignatureVerifier`（WinVerifyTrust + Catalog，结果按 路径+大小+时间 缓存）
- `ProcessDetector`：名称/路径/命令行/父进程
- 受保护进程处理：`ACCESS_DENIED` → 标 `unavailable` 并在报告列出
- 输出：控制台表格 + JSON

交付：能列出本机全部进程及其风险等级。
验收：与 Process Explorer 进程数一致（±2 内）；对 Defender/受保护进程不崩溃、不卡住。

## Phase 2 — 判定引擎 + 报告（1 周）

- `ScoringEngine`：单条分、组合规则、归一化、去重
- 白名单衰减 + 过期检查
- `ReportWriter`：JSON（机器读）/ HTML（人读，单文件内联 CSS）/ 文本
- 报告含：执行摘要、等级分布、按进程分组的证据、未检查项清单、规则版本

交付：一份可发给运营的 HTML 报告。
验收：手工构造 3 个场景（干净机、装了 Cheat Engine、装了无签名注入器），等级分别落在 信息/可疑/高度可疑。

## Phase 3 — 文件扫描（4 天）

- 只读遍历（`FindFirstFileEx` + `FILE_FLAG_OPEN_REPARSE_POINT`，跳过符号链接防环）
- 名称规则 + SHA256（流式，1MB 缓冲；先比 size 再算哈希，省 90% IO）
- 限制：`maxFiles / maxDepth / maxSizeMB`，超限即停并注明"扫描不完整"
- 哈希结果落本地缓存（路径+大小+修改时间 → sha256）

交付：`probe scan --files` 能在 2 分钟内跑完用户目录。
验收：不触碰 `C:\Windows`（靠 excludeGlobs）；重复扫描第二次走缓存，速度提升 5 倍以上。

## Phase 4 — DMA 用户态初筛（4 天）

- WMI：`Win32_PnPEntity` 拿 `PNPDeviceID` 解析 `PCI\VEN_xxxx&DEV_xxxx&SUBSYS_...&REV_xx`
- WMI 资源类：`Win32_PnPAllocatedResource` + `Win32_DeviceMemoryAddress` 近似 BAR 大小
- SetupAPI：`SetupDiGetClassDevs(GUID_DEVCLASS_...)` 补 `DEVPKEY_Device_BusNumber/Address`、驱动名、服务名
- VID/DID 规则比对 + 白名单
- 无内核时的输出：设备清单 + 初步等级 + 明确标注"配置空间未采集"

交付：`probe scan --dma` 输出前 20 个 PCI 设备与命中项。
验收：与设备管理器一致；对无 DMA 板卡的机器零命中（不能靠 Xilinx VID 就报警）。

## Phase 5 — 内核只读配置空间枚举（1.5 周）

- WDM 驱动 `pcieenum.sys`：
  - `DriverEntry` 建控制设备 `\Device\PcieEnum` + `\DosDevices` 符号链接
  - 枚举：`IoGetDeviceInterfaces` 或 `IoGetAttachedDeviceReference` 遍历 PDO 栈
  - 读配置空间：向设备栈下发 `IRP_MN_READ_CONFIG`（`BusInterfaceType = PCIBus`），**不访问物理内存、不映射 BAR**
  - 采集：VID/DID/REV/ClassCode/Subsystem、Capability 链表（遍历 `Capability ID` 链）、BAR0-5 大小（写全 1 回读法，需在**只读枚举阶段跳过写操作**，改用注册表/资源报告取大小）、MSI/MSI-X 存在性
  - IOCTL：`IOCTL_PCIEENUM_QUERY_ALL`（buffer 输出）→ 返回 UTF-8 JSON
- 用户态 `DriverClient`：安装→启动→IOCTL→停止→删除，全链路 try/finally 保证卸载
- 失败策略：`degrade`（用户态结果照出）

交付：驱动 + 客户端，一条命令出完整 PCIe 配置空间 JSON。
验收：与 RW-Everything/PCIScope 的配置空间读数一致（抽样 10 个设备）；扫描结束 `sc query pcieenum` 必须为不存在；连续跑 20 次无蓝屏、无句柄泄漏。

## Phase 6 — 硬化与兼容性（1 周）

- 按 `13_兼容性测试矩阵.md` 逐项过 EAC / BE / Vanguard / ACE / GameGuard
- 性能：全量扫描 ≤ 60s（不含文件深扫）
- 异常：拔网线、断驱动、权限不足、非管理员运行，全部要出报告而非崩溃
- 打包：单文件 self-contained exe（`-p:PublishSingleFile=true`），驱动单独目录

交付：`probe.exe` + `pcieenum.sys` + `rules\` 的可分发压缩包。
验收：干净 Win10 21H2 与 Win11 23H2 各跑一遍通过。

## Phase 7 — WPF GUI（后置，1 周）

- 三栏：设备/进程树 → 详情证据 → 等级与建议
- 报告一键导出，规则热更新，白名单可视化管理
- 不做常驻托盘、不做后台服务

## 里程碑与风险

| 阶段 | 主要风险 | 缓解 |
|---|---|---|
| P1 | 受保护进程拿不到信息 | 明确"未检查"，绝不强开 |
| P3 | 文件扫描触发杀软 | 只读、限速、跳过系统目录 |
| P5 | 驱动签名过不了 | 测试用 testsigning 的隔离 VM；分发用 EV + attestation |
| P5 | 读配置空间写 BAR 会破坏设备 | 只发 READ_CONFIG，BAR 大小走资源报告，不写寄存器 |
| P6 | 与反作弊冲突 | 见测试矩阵；默认不加载驱动 |
