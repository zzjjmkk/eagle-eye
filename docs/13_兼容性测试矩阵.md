# 设计 04：与主流反作弊的兼容性测试矩阵

## 一、先定三档运行模式

| 模式 | 内容 | 触发方式 | 默认 |
|---|---|---|---|
| **M0 纯用户态** | 进程/文件/签名/端口，WMI+SetupAPI 设备枚举 | `--no-driver` | ✅ 默认 |
| **M1 PnP 只读** | M0 + SetupAPI 深度属性 + WMI 资源类近似 BAR | `--dma` | ✅ 开启 |
| **M2 内核配置空间** | M1 + `pcieenum.sys` 一次性枚举后卸载 | `--dma --kernel` | ❌ 仅诊断机 |

设计目标：**M0/M1 在任何反作弊运行时都必须零冲突**；M2 只在没有游戏在跑、或售后诊断机上用。

## 二、矩阵总表

判据统一为：①游戏能进对局 ②连续 10 分钟无踢出/无完整性告警 ③反作弊服务无异常退出 ④系统日志无 7000/7026/蓝屏 ⑤我方进程不被终止。

| 反作弊 | 形态 | M0 | M1 | M2 | 关键风险点 | 通过判据补充 |
|---|---|---|---|---|---|---|
| **EasyAntiCheat** | 内核驱动 + 用户态服务 | 预期零冲突 | 预期零冲突（SetupAPI 只读枚举） | 需 EV/attestation 签名；自签驱动在 Secure Boot 下直接加载失败 | 对我们的**进程句柄请求**敏感，尤其 VM_READ | 事件日志无 EAC 驱动加载失败；游戏内无 "Game integrity" 报错 |
| **BattlEye** | 内核驱动 BEservice | 零冲突 | 零冲突 | 同上；BE 对驱动黑名单较激进 | BE 会枚举可疑进程名，工具名不要伪装成系统进程（伪装反而高风险的误判）；不要读游戏进程内存 | BE 服务进程持续运行；无 "BattlEye: Client not responding" |
| **Vanguard** | 开机自启内核驱动（vgk），要求 Secure Boot + TPM2.0 + HVCI | 零冲突（前提：不做任何句柄提权） | 零冲突 | **基本不可行**：开 Secure Boot 时装不了自签驱动；关 Secure Boot / 开 testsigning 又违反"不改系统安全配置" | Vanguard 对**任何**向受保护进程 OpenProcess 的行为都严格；HVCI 下即使有签名也会校验 | 开启 Vanguard 机器上仅验证 M0/M1；M2 结论写"不支持该环境" |
| **ACE / AntiCheatExpert（腾讯）** | 内核 + 用户态双模块 | 零冲突 | 零冲突 | 需正式签名；ACE 对无模块内存/跨进程句柄检测强，但**我们不碰内存** | 受保护进程上 `OpenProcess` 会 ACCESS_DENIED，必须优雅跳过 | ACE 服务无重启；无 "安全组件异常" 弹窗 |
| **GameGuard（nProtect）** | 用户态为主 + 驱动 | 零冲突 | 零冲突 | 老版本对调试器极敏感，勿在附加调试器下测 | 与我们的只读枚举无交集；避免同时开 x64dbg/CE | GameGuard 初始化成功（不出现 nProtect 错误码 114/380） |

## 三、逐项测试步骤（每格都要跑）

1. **基线**：干净机装反作弊 + 目标游戏，确认可正常进对局（对照组）。
2. **M0**：游戏运行中执行 `probe scan --no-driver --report out\reports\m0.json`，重复 3 次。
3. **观测**：`Procmon` 过滤 `probe.exe`，导出 `OpenProcess` 行，确认 `Desired Access` 只含 `0x1000 (QUERY_LIMITED_INFORMATION)`。
4. **M1**：`probe scan --dma`，观测 `SetupDiGetClassDevs` / WMI 查询耗时，确认游戏帧率无可见抖动。
5. **M2（隔离机）**：`probe scan --dma --kernel`，扫描前后各跑 `sc query pcieenum`，确认服务不存在。
6. **事后**：24 小时后检查账号状态（排除延迟处罚）；检查 `Get-WinEvent -LogName System -Id 7000,7026,41`。

## 四、必测的"红线"检查（自动化）

`tools\verify-no-touch.ps1` 在 CI 里跑，任何一条不通过即阻断发布：

| 检查 | 期望 |
|---|---|
| 源码中 `PROCESS_VM_WRITE` / `PROCESS_VM_READ` | 0 处（读 PEB 场景单独白名单注释） |
| `WriteProcessMemory` / `VirtualAllocEx` / `CreateRemoteThread` | 0 处 |
| `SetWindowsHookEx` / `SetWinEventHook` | 0 处 |
| `ObRegisterCallbacks` / `PsSetCreateProcessNotifyRoutine` | 0 处（驱动源码） |
| 驱动 IRP 处理 | 只允许 `IRP_MJ_CREATE/CLOSE/DEVICE_CONTROL`，`IRP_MN_READ_CONFIG` 出站 |
| 驱动写 PCI 配置空间 | 0 处（禁止 `IRP_MN_WRITE_CONFIG`） |
| 运行时 `bcdedit` / 注册表安全项写入 | 0 处 |
| 驱动卸载 | 每次扫描后 `ServiceExists == false` |

## 五、结论与建议

- **发布版只发 M0/M1**，驱动不进默认包。这样 EAC/BE/Vanguard/ACE/GameGuard 全部处于"我们只是另一个只读枚举工具"的关系，冲突面接近零。
- **M2 定位为售后/取证工具**，只在客户机没有游戏运行、或明确授权的诊断场景使用，且必须正式签名。
- 任何反作弊环境下出现异常，第一步看我们的 `AuditLogger` 日志确认"我们到底请求了什么"，再和反作弊日志对时间线。
